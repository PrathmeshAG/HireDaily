3c) CRON_SECRET KYA HAI AUR KAISE LAGATE HAIN
--------------------------------------------------------------------------
Kya hai: ek password jo backend ke "timer" pages (/api/cron/daily aur /api/cron/health) ko
bachata hai. Ye pages kaam karte hain: token check, deleted jobs check, daily summary message bhejna.
Agar ye pages bina password khule hote to koi bhi unhe baar baar chala sakta. Isliye CRON_SECRET set
na ho to ye pages band rehte hain (503).
KAB ZAROORI: sirf tab jab daily summary / scheduled checks chahiye. Uske liye alert channel
(Telegram/email/webhook) bhi chahiye, warna message jaayega hi nahi. Abhi alerts off hain, to skip karo.
Token FAIL hone ka alert CRON ke bina bhi turant aata hai (jab reply fail ho).

Kaise lagayein (jab alerts on karo):
 1. Ek lamba random text banao. Windows PowerShell:
      [guid]::NewGuid().ToString("N") + [guid]::NewGuid().ToString("N")
 2. Vercel > hiredaily-backend > Settings > Environment Variables > CRON_SECRET = wo text (Production).
    Phir backend REDEPLOY.
 3. Timer chuno (koi ek):
    A) Vercel Cron: backend/vercel.cron.example.json ka naam vercel.json karo (backend folder mein), redeploy.
       Vercel khud "Authorization: Bearer <CRON_SECRET>" bhejta hai. Hobby plan = din mein sirf 1 baar.
    B) cron-job.org (free): URL https://hiredaily-backend.vercel.app/api/cron/daily
       Schedule: roz 21:00 IST. Header: Authorization = Bearer <CRON_SECRET>
 4. Test (terminal):
      curl -H "Authorization: Bearer <CRON_SECRET>" https://hiredaily-backend.vercel.app/api/cron/health
    {"ok":true,...} aaye to sahi. Bina header ke 401 aana chahiye.
 5. Settings > "Alerts, tracking and safety" mein "Scheduled checks: enabled" dikhna chahiye.

5b) KISI USER KO REPLY/DM NAHI GAYA - KAISE DHUNDHEIN
--------------------------------------------------------------------------
Pehle dekho kaunsa case hai:
 A) Logs mein us username ke liye "Comment reply failed: An unknown error..." = Meta ka temporary error.
    Ab auto-retry hota hai. Phir bhi fail ho to Logs > "Retry failed" ya Manual Send.
 B) Logs mein "rule matched ... SKIPPED: cooldown" = rule ka cooldown (default 24 ghante) ne roka, same banda same post par dobara.
    NOTE: cooldown/duplicate yaad rakhna SERVER KI MEMORY mein hota hai (Vercel serverless), restart par reset ho jaata hai.
    Rule mein cooldown "None" kar do to ye band.
 C) Logs mein us username ka KOI entry nahi, par Instagram par comment hai = webhook server tak pahuncha hi nahi, ya reject hua.
    Vercel > backend > Logs mein /webhooks/instagram par status 401 dhundo. 401 = signature reject (ab fix hua, Update 7).
 D) Logs mein "Error / no match" = koi rule match nahi hua (Rules > Unmatched comments dekho).
Har case mein: Manual Send page par jao -> post + username -> comment par buttons se turant bhej do.

MANUAL SEND KI LIMITS (Instagram ke rules, hum badal nahi sakte):
 - Jisne kabhi message nahi kiya use DM sirf us ke COMMENT ka "private reply" ban kar ja sakta hai: ek comment par ek, aur ~7 din ke andar.
 - Kisi bhi random username ko seedha DM nahi bhej sakte.
 - Public reply par ye limit nahi.
 - "Custom DM" us comment ka ek private reply use karta hai. Pehle se DM ja chuka ho to Instagram mana karega.

                confirm karne ke baad link bheja.

                liye bata nahi paya. "Follow nahi karta" ka matlab NAHI hai.

7) VERCEL.JSON KYA HAI (aur kyun chahiye)
--------------------------------------------------------------------------

redirects, headers etc.

chale -> token check + deleted jobs check + daily summary message.
Abhi ACTIVE NAHI hai: file ka naam backend/vercel.cron.example.json hai.
Jab alerts on karo: usse "vercel.json" naam do, redeploy. (Vercel Hobby plan par
cron din mein sirf ek baar chalta hai.) Alerts ke bina iska fayda nahi,
isliye abhi mat lagao. Naya file hone se build mein koi dikkat aaye to hata do.
Alternative: cron-job.org (free) se URL call karwao.
